# BP-04. Просмотр конфигураций языка

## Бизнес-требования

- `BR-CFG-01`: По команде `lman <language> cfg` система должна выводить пути к обнаруженным конфигурационным файлам выбранного языка.
- `BR-CFG-02`: Система должна искать пользовательские и системные конфигурации в известных для языка расположениях.
- `BR-CFG-03`: В результат должны включаться только существующие пути.
- `BR-CFG-04`: Просмотр конфигураций не должен изменять файлы или окружение.
- `BR-CFG-05`: Если конфигурации не найдены, система должна вернуть однозначный результат без аварийного завершения.

## Предусловия

- Язык поддерживается утилитой.
- Для языка определен перечень известных конфигураций.

## Основной сценарий

1. Пользователь выполняет `lman <language> cfg`.
2. Система определяет известные расположения конфигураций языка.
3. Система проверяет существование путей.
4. Система выводит найденные пути.
5. Команда завершается с кодом `0`.

## Альтернативные и отказные сценарии

- Если язык не поддерживается, система возвращает диагностику и ненулевой код завершения.
- Если конфигурации отсутствуют, система выводит пустой результат или понятное сообщение.
- Если отдельный путь недоступен, система продолжает поиск остальных конфигураций.

## Пример

```text
$ lman go cfg
/home/user/.config/go/env
```

## Открытые вопросы

- Нужно ли указывать тип и область конфигурации рядом с путем?
- Нужно ли искать проектные конфигурации относительно текущего каталога?
- Следует ли показывать путь, заданный переменной окружения, если файл еще не существует?
