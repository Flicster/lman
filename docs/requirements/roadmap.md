# Roadmap `lman`

Roadmap содержит направления развития после завершения read-only этапа. Они не входят в текущий BRD и потребуют отдельных бизнес-требований.

## Этап 2. Управление пользовательскими установками

- Каталог доступных версий для ОС и архитектуры.
- Установка версии из доверенного источника.
- Проверка контрольных сумм и подписей артефактов.
- Обновление управляемой установки.
- Удаление управляемой установки.
- Атомарность, блокировки конкурентных операций и откат при ошибке.
- `--dry-run`, подтверждение и неинтерактивный режим.

Системные установки и установки сторонних менеджеров должны по умолчанию оставаться только для чтения.

## Этап 3. Управление активной версией

- Выбор пользовательской глобальной версии.
- Закрепление версии за проектом.
- Декларативный проектный файл для VCS.
- Явный порядок разрешения `project -> global -> system`.
- Обратимая интеграция с shell.
- Диагностика конфликтов `PATH` и поврежденных ссылок.

## Этап 4. Автоматизация и экосистема

- Версионируемый JSON-контракт.
- Автодополнение для поддерживаемых shell.
- Декларативная установка набора языков и версий.
- Работа в CI.
- Пользовательские зеркала и источники.
- Плагины стратегий обнаружения и управления языками.
- Импорт существующей установки под управление `lman`.

## Вопросы перед этапом управления

- Какими языками и версиями `lman` имеет право управлять?
- Где расположен управляемый каталог?
- Какие официальные источники являются доверенными?
- Допускается ли управление установками Homebrew, apt, SDKMAN, pyenv и аналогов?
- Какой формат проектного файла используется?
- Какие shell поддерживаются?
- Какие гарантии отката обязательны?
